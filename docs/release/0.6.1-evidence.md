## Release workflow contract

The manual release workflow performs all of the following before uploading its bundle:

1. installs and tests the Python package on Python 3.12;
2. runs Android unit tests, lint, and `assembleDebug` with strict dependency verification;
3. invokes `scripts/package_release.py` for version `0.6.1`;
4. invokes `scripts/verify_release.py`;
5. runs the packaged installation verification script;
6. verifies the APK signature with `apksigner`;
7. uploads the complete `.dist/*` directory as one workflow artifact.

The workflow is manual (`workflow_dispatch`) and does not publish a GitHub Release.

## Required six-file release set

`scripts/package_release.py` defines exactly these six top-level output files for version `0.6.1`:

1. `comptext-phone-agent-0.6.1-full.zip`
2. `comptext-phone-agent-0.6.1-upgrade.zip`
3. `comptext-phone-agent-0.6.1-source.zip`
4. `comptext-phone-agent-0.6.1-android-debug.apk`
5. `release-manifest.json`
6. `SHA256SUMS`

The three ZIPs are deterministic and use the common root prefix `comptext-phone-agent-0.6.1/`. The packaging script rejects unsafe paths, symlinks, build directories, environment files, private keys, model files, databases, APKs inside source archives, and other forbidden release members.

`release-manifest.json` binds the package to the Git commit and records SHA-256 hashes, sizes, archive kinds, and per-member hashes. `SHA256SUMS` covers the three ZIP files, APK, and manifest.
